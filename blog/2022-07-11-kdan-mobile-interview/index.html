【現在就走！前進企業帶你看】成為 Kdan 人必看 Q&A！新人剛進工作會有前輩帶領嗎？

【現在就走！前進企業帶你看】第二集來了！ 嗨嗨我是Ｚ編，本企劃將會由洧杰、卡斯伯，兩位老師前進前端、設計相關公司，替大家一探究竟 👀

今天前往的是位於台南市的「Kdan Mobile 凱鈿行動科技」 (👩‍🏫 鈿：ㄉㄧㄢˋ，不念 ㄒㄧˋ ）

Kdan Mobile 凱鈿行動科技 小檔案
凱鈿致力於提供生產力與創造力系列軟體服務，讓專業工作者在數位創新浪潮下實現高效管理，發揮創意。
旗下產品包含點點簽（DottedSign）電子簽名服務、Document 365 跨裝置 PDF 文件解決方案、Creativity 365 創意 App 系列、以及 Kdan Cloud 雲端服務。目前已在全球累積 2 億次下載，擁有 1,000 萬名註冊會員。

企業訪談當天凱鈿派出了前端 Roy、後端 William、QA Lila、資深產品經理銘賢 ，非常感謝四位同仁的分享，讓我們更了解凱鈿

成為 Kdan 人必看 Q&A！

Q：想請問一下目前 Kdan 前端、後端團隊人數？ A：現階段 Kdan 全球研發團隊（含海外）加起來超過 100 名，隨著既有產品 Creativity 365、Document 365 和點點簽（DottedSign）的迭代更新、Inspod 新產品的加入，各產品線在技術程度方面都鑽研的蠻深的，目前提供服務的會員人數也在持續不斷增加當中，因應各階段不同的需求，我們需要有更多技術人才加入台南辦公室團隊。

Q：想了解一下目前 Kdan 前端、後端所用的技術？ A：前端工程師 Roy： 前端是用 React 框架，搭配 Next.js，CSS 部分是使用 styled-components，開發過程中會需要寫到單元測試，團隊成員會將功能提交到 GitLab，讓團隊成員進行 Code Review。 A：後端工程師 William： 目前後端是使用 Ruby on Rails，並運用 AWS 架設雲服務，以及 Docker 做容器化。

Q：在 Kdan 的辦公空間可以看到除了辦公桌，還設有許多小型會議室、小隔間，甚至是開放式的討論區，由此可知 Kdan 是很強調團隊合作、溝通的公司，想請問一下以「前端工程師」來說，和其他部門的合作模式是如何進行的？ A：我們比較像是「迭代式開發」，會把整個開發工作拆分成一系列小專案，幫助我們在這開發的過程中，確保每個階段都有充分的討論及測試。 例如會由行銷團隊和 PM 送出需求給我們，開發團隊會先看過一遍，看看有沒有問題。若有需要再討論的部分，會再去找行銷團隊和 PM 討論，這時也會請 UI 加入。 除了和行銷團隊和 PM、後端、設計，必要時也會請 Data team、QA 加入討論， Kdan 很強調團隊合作，所以很鼓勵大家互相協助幫忙、解決問題。

Q：前端、後端新夥伴加入 Kdan，會有前輩帶領嗎？需要注意些什麼呢？ A：前端工程師 Roy： 以前端來說，會先抓一個月的時間給新夥伴，前一個月會有人帶領先處理一些小專案， 請他先試試看。我們有做「前端新人訓練手冊」，上面會寫一些需要了解的東西（例如：JavaScript、進階的 CSS 和 React 的相關概念） 在這一個月當中，會請新人寫單元測試，每日或每週給資深工程師回報，我們會給他一些反饋 一個月後進行驗收，若沒什麼大問題，就可以請新人進入正式的開發工作。 A：後端工程師 William： 新人一般都沒有碰過 Ruby on Rails，所以我們會提供一本「Ruby on Rails 的聖經」，讓新人有三個月的時間可以自己學習。 後端團隊每天早上都有會議，會請新人報告自己的進度（例如：目前的學習狀態） 學的差不多後，我們會設立一個情境題，請他規劃並實作出 API，這個階段主要會看新人的 API 有無符合要求和商業邏輯是否合理，若 API 可能沒有符合標準，但商業邏輯是合理的，就還可以培養。 前三個月，會有很多東西要弄，我們大概會拆八週，讓新人動手去做，最後彙整報告， 前輩也會給回饋，以上都通過後，我們就會帶著新人認識公司目前脈絡，嘗試和行銷、 PM 練習跨部門溝通，之後就可以慢慢進入狀況。新人第一次自己實作，通常會被大改一輪，需要花很多時間思考，但其實這是蠻必要的，會是一小段痛點。

Q：和其他公司相比，Kdan 除了前端、後端，還設有 QA（Quality Assurance 軟體測試工程師）團隊，這蠻少見的，想了解 QA 在做什麼？所需要的特質有哪些呢？ （PM：QA 你可以介紹一下你自己） A：軟體測試工程師 Lila： 其實我是森林系背景，在學校是抓真的蟲（笑），會成為 QA 有點像一路走過來，因為森林系需要做戶外的空間調查，進而處理到 data 分析，數據也需要和空間做結合，所以就有接觸到 GIS（地理資訊系統），但因為我不是技術相關背景，所以一開始是先幫 RD 整理外面的需求和推廣產品，後來一路走到現在。 有軟體開發、測試相關經驗等硬實力當然是加分的，但招募上更重視軟實力和發展潛力， 例如：邏輯是否清晰、表達能力如何，我們希望新人遇到問題可以和團隊有更有效率的溝通，這是蠻重要的。

Q：剛有提到 QA 和一般工程職位不太一樣，不太要求硬實力，那工作上會需要寫程式嗎？ A：軟體測試工程師 Lila： 不一定，視你的能力、背景而定。像凱鈿目前 QA 團隊有四位，其中兩位有 coding 背景，可以多輔助做自動化測試腳本建置、或壓力測試，另外兩位技術背景不深，則負責手動測試。 像我主要負責「手動測試和測試的規劃」，因為我沒有相關技術背景，是比較概念化觀念，所以比較能夠去思考這個專案、產品要做到什麼程度，把想法彙整成目標，再和部門成員討論，讓他們了解需求，進而去執行。 QA 部門其實比較能接受來自不同背景的人，只要有明確的學習目標、對解決問題有熱忱，我們就會協助放在適合的位置，讓新人去發展，因為我們也會希望除了工作，也可以讓每個人做自己喜歡的事。

Q：大家普遍對 QA 這個職位不太熟悉，想了解你們會怎麼帶領新人呢？ A：軟體測試工程師 Lila： QA 部門也有新人訓練手冊，規劃著 QA 所具備的查核清單，新人剛進來我們會以比較開放的角度，讓他去玩玩公司的產品，或是我們本來規劃要請他負責的產品，會希望新人先以客觀的角度，去了解產品，可以有自己的對產品的優缺點看法，近而培養觀察角度，也會讓他試跑看看一些更新的測試，後來才會試試看比較大功能、複雜的功能。 Lila 特別做了一份 QA 日常工作內容、所需人格特質簡報，有興趣的同學可以參考唷： 成為 Kdan QA

Q：聽說 Kdan 的女性員工比男性多？ A：Kdan 通常男生多的部門，女生也會有一定的比例，但女生比較多的部門，幾乎清一色都是女生，所以基本上凱鈿是女生多的公司（笑)。

Q：Kdan 打造了一系列的生產力 & 創造力 App ，希望用更創意、貼近人性的方式，提高用戶工作效率，那想請問在人才需求上會希望有什麼人格特質呢？ A：資深 PM 銘賢 經理： 我們希望可以有更多不同背景的新人加入，幫助 Kdan 有更多不一樣的軌跡，若有用戶行為分析、專案管理、產品經理或產品的經驗會更好，因為我們不希望大家只專注在技術方面，而是可以更全面的思考，用數據來分析、做決策，這樣再加上技術有一定的標準，就會更加分。 Kdan 有 Data team，所以很多時候會需要數據上的輔佐來驗證、判斷怎麼做才是比較好的，我們比較傾向希望夥伴提出自己的想法，來告訴團隊還可以怎麼做。
